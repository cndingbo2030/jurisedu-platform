## 0. 文档信息与阅读约定

### 0.1 定位

本文件是 **Juris & Edu Intelligence** 教育 AI SaaS 平台的**总工程文档**，覆盖从领域模型到部署运维的完整工程视图，并对两大技术子系统——**AI 互动教学（Affect-Adaptive Tutoring）** 与 **可问责生成引擎 TIDAR-KAG**——做工程级深挖。

平台由两根技术支柱支撑：

1. **AI 互动教学**：从"一句话 / 一段话 / 一张图片 / 一个主题 / 一个内容包"这样的最小输入，编译出结构化的自适应课程与多模态媒体（含视频），并在投放时根据学习者的**表情、语音韵律、语言作答**实时决定内容节点是重复、深入、推进、纠偏还是先做情绪调节。
2. **TIDAR-KAG 可问责生成**：一个**领域中立**的知识增强生成（KAG）问责框架，为高风险决策提供来源接地、时点正确、冲突可裁决、可弃权、可复盘的输出保证。教育为其主要落地实例。

## 2. 领域模型与角色权限

### 2.1 两个世界（Two-World Architecture）

平台在领域上分为两个互不混淆的"世界"，是角色边界（C6）的根因：

| 世界 | 主体 | 是否有撮合 | 说明 |
|---|---|---|---|
| **机构世界** | 机构管理员 + **机构教师** + 其名下学生 / 家长 | ❌ 无撮合 | 机构自有招生，教师在机构内授课；教学、评测、AI 助教、审计齐备，但**不出现任何"撮合 / 找学生 / 接单派单 / 担保市场"入口** |
| **独立执业世界** | **独立补习老师** + 家长 / 独立学习者 | ✅ 有撮合 | 独立老师通过平台**找学生、接单**；平台提供撮合引擎、担保、托管与争议仲裁（见 §6） |

> **工程含义**：撮合相关模块、路由、前端版块**只对 `role=independent_tutor` 及 `parent/learner` 的需求侧开放**，对 `role=institution_teacher` 一律不可见、不可达。这是一条**权限不变量**，必须在后端授权中间件与前端路由守卫**双侧**强制（见 §8.4）。

### 2.2 角色与权限（RBAC）

| 角色 | key | 撮合 | 关键能力 |
|---|---|---|---|
| 平台管理员 | `admin` | 治理 | 运营、审核、合规、撮合治理、担保仲裁、评测与配额 |
| 机构管理员 | `org_admin` | ❌ | 机构成员/班级/课程管理、机构级报表与审计 |
| **机构教师** | `institution_teacher` | ❌ | 备课（AI 生成课程）、授课投放、评测、AI 助教、学情看板；**无撮合视角** |
| **独立补习老师** | `independent_tutor` | ✅ | 上述教学能力 **＋ 找学生（地图/能力/时间）＋ 接单 ＋ 撮合市场 ＋ 担保** |
| 家长 | `parent` | 需求侧 | 找老师、订购课程/课程包、确认接单、查看学情、托管支付 |
| 学生（学习者） | `learner` | — | 上课、AI 自学、互动作答；**单一角色 + 接入方式标识**（§2.3） |

RBAC 落地：后端以 **`internal/security`（鉴权/授权）+ `internal/middleware`（路由级守卫）** 为核心（✅ 基座已实现鉴权与中间件框架）；教育角色矩阵与撮合可见性为 🟡 **在其之上扩展**。

### 2.3 学习者的三种接入方式（单角色 + 接入标识）

**结论（既定设计）**：学习者是**单一 `learner` 角色**，用"接入方式（access mode）"标识区分来源与计费/数据归属，而非三个不同角色。三种接入共用同一套学习引擎与 AI 教学能力。

| 接入方式 access_mode | 谁提供内容/席位 | 计费/数据归属 | AI 自学 |
|---|---|---|---|
| `institution` 机构/学校学生 | 机构/学校（席位制） | 机构；数据在机构租户域 | ✅ 可用 |
| `self_directed` 独立自学用户 | 学习者自订阅 | 个人订阅 | ✅ 可用（AI 自学服务） |
| `parent_purchased` 家长订购 | 家长购买课程/课程包或撮合课时 | 家长账户；关联学习者 | ✅ 可用 |

> **工程含义**：`learner` 主体上挂 `access_mode` 与 `provisioned_by`（机构/自己/家长），**授权、计费、数据分域**均由接入方式驱动；学习引擎（§4）无需感知来源。AI 自学对三类学习者**一致开放**（既定设计）。

### 2.4 核心领域实体（概念模型，详见 §7 数据模型）

`Tenant`（机构/平台租户）· `User`（多角色）· `Institution` · `Class` · `IndependentTutor` · `Parent` · `Learner`（+`access_mode`）· `Course/CoursePack` · `Lesson`→`AdaptiveLessonGraph`（§4）· `Order`/`Dispatch`/`Escrow`（§6）· `KAGGraph`（§5，Neo4j）· `AuditLedger`（哈希链，§8）。

## 4. AI 互动教学子系统（Affect-Adaptive Tutoring）— 深挖

> **形式化底座**：论文《From Minimal Intent to Adaptive Delivery》(SSRN 7311778)。本节给出工程落地；凡定理/保证以论文为准。
> **状态**：形式化设计 🟡 + 复用基座出口（aigateway/audit/privacy ✅）。**仿真为合成数据、非真人实测（论文明示）**。

### 4.1 子系统定位与两层结构

一对一"掌握式"辅导的学习增益很大，但规模化要同时解决两件事：**创作**（把老师意图变成结构化互动课程）与**投放**（在不确定下逐轮决定重复/深入/推进/纠偏/情绪调节）。本子系统用两层解决：

```
最小意图                         生成层 Lesson Compiler                      自适应课程图 ALG + 多模态媒体
(一句话/一段/图片/主题/内容包) ──▶ 接地→分解→合成→渲染→蕴含门 (§4.2) ──▶ (§4.3 概念×深度节点图 + 视频)
                                                                              │
学习者(表情/语音/作答) ──▶ 投放层 Delivery Controller (POMDP, §4.4) ──▶ 每轮动作∈{推进,重复,深入,纠偏,情绪调节}
                          多模态信念更新 · 保形掌握门 · 子模诊断 · 有界挫败活性
```

### 4.2 生成层：Lesson Compiler（最小意图 → 课程 + 视频）🟡

把**最小输入**编译为 §4.3 的 ALG 与配套媒体，五阶段流水线；**关键工程点是"接地/蕴含门"**——机器生成的课程只教"被批准来源蕴含"的内容，这是把 AI 生成放进课堂的前提。

| 阶段 | 动作 | 依赖（走 aigateway ✅ 出口） |
|---|---|---|
| ① 接地 Ingest & Ground | 归一化输入；图片走视觉-语言编码；主题/图片检索或挂载**批准来源 S**（内容包/教材/权威参考），RAG 式接地 | VLM、检索 |
| ② 分解 Decompose | 抽取概念集与先修关系 `≺` | LLM |
| ③ 合成 Synthesize | 逐深度合成节点：讲解、例题、题目（自动出题）、提示 | LLM |
| ④ 渲染 Render | 生成媒体，含**解释性短视频** | 文生视频、TTS |
| ⑤ 门 Gate | **仅当节点每条断言都被 S 蕴含才放行**；否则拒绝或转人工复核 | 句级 NLI 蕴含检查 |

**接地门（工程不变量）**：设 `E(p, S)∈{0,1}` 为句级蕴含判定，仅当命题 p 被来源 S 蕴含才返回 1。节点 n 被"接地于 S"当且仅当 `∀ p∈assert(n): E(p,S)=1`。**编译器只放行接地节点。**
> 这与 §5 TIDAR-KAG 的句级蕴含门同源——教育课程生成复用同一套"只教可溯源内容"的忠实性机制。**忠实性保证只与蕴含器 E 的可靠性一样强，不多不少**（论文 Prop 1 + Assumption 1）。

### 4.3 自适应课程图 ALG（Adaptive Lesson Graph）🟡

ALG 是生成层与投放层的**交汇数据结构**，是一张"概念×深度"的图，而非线性脚本（线性脚本无法表达"换种方式再讲一遍""退回一步"）。

- 定义：`G = (C, N, ≺, lvl, Θ)`
  - `C` 概念集；`N=∪_c N_c` 内容节点（按概念划分）；`≺` 先修偏序
  - `lvl: N→{0,1,…,L}` 深度：**0=补救 / 1=核心 / 2+=纵深**
  - `Θ(n)` 载荷：讲解 / 例题 / 题目 / 提示 / 反馈 / 媒体；`assert(n)` 该节点教/测的命题集
- 节点是投放层可投放的最小单元；深度让"同一概念"能更温柔地重讲（降到 lvl 0）或更深入（升 lvl），而不离开该概念；`≺` 定义合法的"推进/纠偏"移动。

### 4.4 投放层：Delivery Controller（POMDP 决策）🟡

把辅导建模成**部分可观测马尔可夫决策过程 (POMDP)**：潜在学习者状态不可直接观测，只能从多模态信号推断。

**潜在状态**：`s_t = (z_t, e_t)`，`z_t∈{0,1}^K` 为各概念**掌握向量**，`e_t∈[0,1]` 为**投入/情绪**标量（可推广到 valence–arousal 二维）。

**动作**：`a = (move, c, d)`，`move∈{推进 ADV, 重复 REP, 深入 DEEP, 纠偏 REM, 情绪调节 REG}`。

**观测**：`o_t = (x_t, u_t)`——`x_t∈{0,1}` 作答正确性（语言通道，来自作答/ASR，精确）；`u_t∈R^m` 多模态情感特征（面部动作单元 + 语音韵律）。REG 只产出 `u_t`。

**奖励**：`R = w_m·(掌握增量) + w_e·φ(e) − w_c`（掌握增益 + 投入保全 − 每轮成本）。

#### 4.4.1 因子化信念与更新

精确 POMDP 规划不可解；用领域可证成的**因子化信念**降维：
`b_t(z,e) = μ_t(e)·∏_c β_{t,c}^{z_c}(1−β_{t,c})^{1−z_c}`，`β_{t,c}=P(z_{t,c}=1)`。

- **掌握子滤波（知识追踪 BKT）**：对被测概念 c，先按作答做贝叶斯后验，再做学习转移；可用深度知识追踪替换，只要仍输出**标定良好**的 `β`。
- **投入滤波（有界可靠性）**：**诚实建模情感通道**——不直接观测 `e`，而观测 `y_t=e_t+η_t, η∼N(0,σ_r²)`，可靠性=精度 `1/σ_r²`。**因为"从面部构型可靠读出离散情绪"在科学上受质疑（Barrett 等 2019），`σ_r` 不小**；任何依赖 `ê` 精度的保证都必须如此声明。用卡尔曼式更新 `ê_t = ê_{t−1}+k_t(y_t−ê_{t−1})`；`σ_r→∞` 时增益 `k_t→0`——**噪声通道被忽略而非被误导**，退化为纯掌握式辅导。这是 D3 的形式含义。

#### 4.4.2 三个带保证的机制

1. **保形校准掌握门**：只按点估计 `β≥τ` 推进无法控制"过早推进"率（β 可能失准）。改用**分布无关的分裂保形**校准：在可交换校准集上以"真标签"非一致性分数定阈值 `q̂=⌈(n+1)(1−α)⌉`，形成掌握标签的保形集，**仅当集合为单点 {已掌握} 才推进**，否则继续教。→ **定理：门触发的过早推进率 ≤ α**（论文 Thm 1，边际保证；`R_max` 活性逃逸不受该门控制，见诚实附注）。
2. **子模/模块化诊断选择**：需要选测哪些概念以最快降低不确定性时，最大化 `f(Q)=I(z;X_Q)`。因子化+每概念单探时 `f` **模块化**，贪心即最优；探针跨概念/信念相关时 `f` 单调**子模**，贪心 (1−1/e) 最优（论文 Prop 3）。
3. **有界挫败活性**：每概念**任意类型**交互至多 `R_max` 次即推进（`r_c` 对重复/纠偏/情绪调节**一律计数**）；一旦 `ê<θ` 或连错达 `F`，下一步必为 REM/REG（先于重复分支）。→ **定理：进程或干预 + `K·R_max` 步内终止**（论文 Thm 2，对任意（含对抗）观测流成立）。

#### 4.4.3 投放策略（每轮，概念 c）

```
输入: 各概念信念 {β_{t,c}}, 投入估计 ê_t, 交互计数 r_c(计入所有交互), 连错 cf_c;
     参数 τ, α, θ, θ_reg, F, R_max
1  用 §4.4.1 从上一观测更新 β_{t,c} 与 ê_t
2  若 Gate(β_{t,c}, α) = {已掌握}:        return (ADV, c)     # 保形掌握门 (D2)
3  否则若 r_c ≥ R_max:                    return (ADV, c)     # 有界重复→活性 (D5)
4  否则若 ê_t<θ 或 cf_c≥F:                                    # 检测到挫败 (D3)
5      return  ê_t<θ_reg ? (REG,c) : (REM,c, 深度−1)
6  否则:                                  return (REP,c,核心)  # 有效练习
```

### 4.5 多模态感知与未成年人隐私（工程要点）

- **感知通道**：面部动作单元（AU）+ 语音韵律 + ASR 作答；均走 **aigateway ✅** 统一出口。
- **诚实前提（不可越界）**：情感估计**不可当作已确证情绪**（Barrett 2019）。系统里情感只是**被支配的弱证据**，只触发**支持性动作**（纠偏/情绪调节/放慢），**绝不惩罚性**。论文仿真显示：即使情感通道噪声很大，收益仍稳（因为它"帮不了也害不了"）。
- **未成年人数据（合规硬要求，见 §8）**：情感感知对学生（多为未成年人）**须显式知情同意（未成年人为监护人同意）、最小化（优先端上计算特征、只留估计不留原始人脸/语音）、非惩罚**；**不做超出"运行时估计"的情感留存**，学习者侧有清晰披露与控制。
- **公平性**：面部/语音情感识别存在人群偏差；投放前须做**分群差异审计**（§8）。

## 5. TIDAR-KAG 可问责生成子系统（域中立）— 深挖

> **形式化底座**：论文《Time-Indexed Defeasible Argumentation with Calibrated Risk》(SSRN 7311378)。
> **域中立声明（C2）**：本节框架**与领域无关**；以"教育 / 通用高风险决策"为例证，不含任何特定行业专属内容。
> **状态**：KAG 引擎与审计/图库 ✅（基座 `kag` 模块 + Neo4j + audit）；四层形式化与保形门为 🟡 在其上落地。

### 5.1 为什么需要它

大模型被越来越多地用于**有后果的决策**，而这些决策恰恰需要模型不原生具备的性质：**来源归属、按当时生效版本的正确性、冲突准则的有原则裁决、可辩护的弃权策略、可复盘的审计链**。检索增强只提供上下文，不提供上述任何保证。TIDAR-KAG 在一个知识增强生成器之上**组合四层**来补齐这些性质。

### 5.2 四层架构

```
          输入查询 (as-of 时点 t)
                 │
   ┌─────────────▼──────────────┐
   │ KAG 双通道 (§5.7)            │  符号通道(图) ∥ 语义通道(检索)，句级蕴含门把关
   └─────────────┬──────────────┘
   L1 TCG  时间索引证据图 ──▶ AsOf(t) 只取当时生效证据
   L2 PRL  可废止规则层   ──▶ 专家准则=规则(grounds/defeaters)，shadow→active 才生效
   L3 AE   论辩引擎        ──▶ Dung 有根语义, 每论点 IN/OUT/UNDECIDED, 确定性不动点
   L4 CCG  保形校准门      ──▶ 单点则释放, 否则弃权到人工
                 │
     哈希链账本 (每步决策可复盘) + JEanchor 证据排序
```

### 5.3 L1 — 时间索引证据图 TCG（Time-Indexed Certainty Graph）🟡（图库 ✅）

- 每条证据/边带 `valid_from / valid_to`（生效区间）。
- 时点算子 `AsOf(t)`：只返回在 t 时刻生效的子图——**保证"按当时版本正确"**（评分标准、课程标准、指南、法规版本都会更新，需按当时生效版本判定）。
- 差分算子 `Diff(t1,t2)`：解释"两个时点之间变了什么"。
- **落地**：Neo4j（`neo4j-go-driver/v5` ✅），时间属性 + `AsOf` 查询模板；`kag` 模块 ✅ 已是符号通道承载。
- **性质**：Prop 1 时序可靠性——AsOf(t) 结论只依赖 t 时刻生效证据。

### 5.4 L2 — 可废止规则层 PRL（Prioritized Rule Layer）🟡

- 专家准则表示为**可废止规则**：`conclusion / grounds / defeaters / author / mode∈{shadow, active}`。
- **shadow→active 提升**：新规则先影子运行（只观察、不影响输出），**经审计后才提升为 active** 生效。→ 可控上线、可回滚。
- **落地**：规则存关系库 + 配置（现有 `config/.../*rule*.txt` 是同构的规则/提示制品 ✅ 佐证该模式可行）；提升走审计（audit ✅）。

### 5.5 L3 — 论辩引擎 AE（Argumentation Engine）🟡

- 把 L2 规则实例化为论点与攻击关系，按 **Dung(1995) 有根语义**裁决冲突：每个论点判为 **IN / OUT / UNDECIDED**。
- **确定性不动点**：从 ∅ 单调迭代到有根扩张；因格有限，Kleene 迭代必达最小不动点，且每步至少加入一个论点，**≤|A| 步终止**。→ **同输入同裁决，可复现**（Prop 2，Knaster–Tarski/Kleene）。

### 5.6 L4 — 保形校准门 CCG（Calibrated-risk Confidence Gate）🟡

- 基于**分裂保形预测**：在可交换校准集上定阈值 `q̂=⌈(n+1)(1−α)⌉`，对输出标签形成保形预测集。
- **释放规则**：预测集为**单点**→释放该自动决策；否则→**弃权到人工**。`α<1/(n+1)` 时阈值不存在，约定 `q̂=+∞`、`C_α=Y`，不形成单点、门弃权（诚实边界情形）。
- **保证（Thm 1 + Cor 1，诚实版）**：可交换性下**边际覆盖 ≥1−α**；由此得**联合释放错误有界** `P(释放 ∧ ŷ≠y) ≤ α`。**注意（Remark 1，诚实关键）**：这是**边际/联合**保证，**不是"每次释放"的条件保证**；条件于"已释放"的错误率可能超过 α，且在校准与部署分布漂移下退化。

### 5.7 KAG 双通道 + 句级蕴含门

- **双通道**：**符号通道**（TCG 图上的结构化证据）∥ **语义通道**（检索到的文本证据）。两通道以阈值 0.7 融合（🎯 演示口径阈值，可调/需标定）。
- **句级蕴含门（忠实性）**：每条**被断言的句子**必须被**批准来源蕴含**（NLI 判定）才允许输出——**不输出无来源支撑的断言**。
- **性质**：Prop（忠实性）——在"蕴含器不接受未蕴含句"(Assumption 1) 下，释放文本**无未被来源支撑的断言**。**与 §4.2 教育课程生成门同源**。

### 5.8 JEanchor 证据排序 + 哈希链账本

- **JEanchor**：对候选证据/结论做多因子排序（新近性、权威性、图上支撑度、语义相关度等），5 步流程，输出**带引用理由**的排序，供释放与人工复核使用（🎯 因子权重为演示口径，需标定）。
- **哈希链账本**：每步决策（证据、规则、裁决、释放/弃权、理由）**链式哈希**记录，**可回放**。→ 直接由基座 **audit ✅**（per-actor 链验证、同步失败即报、条目哈希覆盖全部取证字段）承载。

## 6. 撮合市场：找学生 · 接单派单 · 担保（仅独立补习老师）🟡

> **角色边界（C6）**：本章能力**只属于 `independent_tutor` 与需求侧 `parent/learner`**；**机构教师完全不可见**（§2.1 权限不变量，§8.4 双侧强制）。

### 6.1 双向撮合与"找学生"

- **需求侧**（家长/独立学习者）："找老师"发布需求。
- **供给侧**（独立老师）：**"找学生"**——按**地图 / 能力 / 时间**发现并接单（不是"找老师"）。
- 两侧由同一 **JE 撮合引擎**匹配，**每条匹配都给出理由**。

### 6.2 三路径接单派单模型（单状态、无双派）

| 路径 | 流程 | 关键规则 |
|---|---|---|
| ① 家长直选 → 老师接单 | 家长挑选 → 老师接受 | 家长主动 |
| ② JE 智能派单 → 老师接单 | JEanchor 排序派单 → 老师接受 | **拟合度 <85%（🎯 演示口径阈值）或敏感情形 → 弃权转人工**；**独占接单窗口**到期未接则**级联**下一位 |
| ③ 老师主动找学生 → 家长确认 | 老师发起/报价 → 家长确认 | 供给侧主动 |

**核心不变量**：**一个订单在任一时刻只有一个状态、只在一处**——**绝不同时派给两位老师**（no double-dispatch）。这是把"接单派单"讲清楚、避免混乱的根因规则。

### 6.3 公平与可信

- **新老师曝光配额**：为新老师保留 **15%（🎯 演示口径）曝光额度**，防止头部锁定。
- **担保 / 托管 / 争议仲裁**：**家长确认且资金进入托管后**才成交，课后放款；全程托管、保险与争议仲裁。
- **可解释**：派单/匹配**带引用理由**（复用 §5.8 JEanchor 的"带理由排序"）。

### 6.4 工程落地

新建 `internal/matching`：`find`（找学生：地图/能力/时间检索）+ `dispatch`（三路径状态机，单状态约束、独占窗口、级联、15% 配额）+ `escrow`（托管/放款/争议）。派单排序复用 JEanchor；理由与状态变更**入 audit ✅ 哈希链**。**撮合路由挂角色守卫，`institution_teacher` 一律 403 + 前端不渲染**。

### 7.1 关系型核心实体（Postgres）

| 实体 | 关键字段（摘） | 说明 |
|---|---|---|

| `course` / `course_pack` | id, owner_id, items[] | 课程/课程包 |
| `lesson` / `alg_node` / `alg_edge` | lesson_id, node(concept,lvl,payload,assert[]), edge(prereq/branch) | **ALG**（§4.3），节点载荷 + 断言集 |

### 7.3 对象存储

生成媒体（视频/图片/音频）、内容包/教材（批准来源 S）、证据附件；引用而非入库，配 CDN。

## 8. 安全与合规

> 复用基座**真实**的安全/合规控制（✅），并按教育场景（未成年人、PDPA）扩展（🟡）。

### 8.1 个人数据保护（PII，✅ 基座）

- **可逆脱敏**：入模前脱敏，**KMS 托管的可逆令牌 `[[PII_type_n]]`**（`internal/infrastructure/privacy`，`DetectPII`）。
- **新加坡 PDPA 场景**：既有实现已含新加坡本地识别模式（NRIC、+65 电话、邮箱、卡号等），**教育侧直接复用于学生个人数据**。
- 原则：**过脱可恢复；欠脱是事故**（既有 owner 定则）。

### 8.2 未成年人与情感数据（🟡 教育扩展，硬要求）

- 情感感知**opt-in**、**监护人同意**（未成年人）、**最小化**（端上算特征、只留估计不留原始人脸/语音）、**非惩罚**（§4.5）。
- **不做超出"运行时估计"的情感留存**；学习者侧清晰披露与控制。
- **公平性**：情感识别人群偏差 → **投放前分群差异审计**为部署前置条件（非事后）。

### 8.3 审计链（✅ 基座）

- **哈希链**：per-actor 链验证；admin 审计写**同步、失败即报**；条目哈希覆盖全部取证字段；提案哈希覆盖 Payload。
- 这既是 §5 TIDAR-KAG 账本，也是 §4 投放"确定性可复盘"的承载。

### 8.4 授权不变量：撮合可见性双侧强制（关键）

- **后端**：撮合路由（§6）挂角色守卫，`institution_teacher` → **403**（`internal/security` + `internal/middleware`）。
- **前端**：路由守卫 + 版块渲染守卫，机构教师**不渲染任何撮合入口**。
- **单侧不足**：必须**后端 + 前端双侧**强制（防绕过/防泄漏），并进 §11 回归测试。

### 8.5 品牌与供应商隔离（✅ 基座）

`aigateway` allow-list（拒绝而非脱敏）+ `ScrubVendor`（大小写不敏感词界正则）+ `brand-leak-scan.sh` CI 阻断门。**工程上确保对外产物不泄露任何内部代号/供应商名**（与 C1 一致）。

### 8.6 计费配额（✅ 基座）

`middleware/plan_cap` 挂在 LLM 路由上；带 `BILLING_V1` kill-switch（**默认放行、DB 错误失败开放**），上线零风险；教育侧用于机构席位/家长订购的用量约束。**生产启用前须装配已核验的限额解析器。**

## 9. API 设计

### 9.1 约定

- 统一经**网关 (:8011)**：鉴权（JWT）→ 角色守卫 → 计划配额 → 路由到后端 (:8080)。
- 风格：REST + JSON；分页/幂等键/错误码统一；所有 LLM 类路由过 `plan_cap` 与 `aigateway`。
- 版本：`/api/v1`。

### 9.2 关键端点（摘，🟡 教育扩展 / ✅ 复用）

| 域 | 方法 路径 | 说明 | 守卫 |
|---|---|---|---|
| 教学·生成 | `POST /api/v1/tutoring/compile` | 最小意图 → ALG+媒体（§4.2），带接地门结果 | 教师(机构/独立) |
| 教学·投放 | `POST /api/v1/tutoring/sessions/{id}/step` | 提交观测→返回下一动作（§4.4） | 教师/学习者 |
| 教学·ALG | `GET /api/v1/tutoring/alg/{lessonId}` | 取课程图 | 教师/学习者 |
| KAG | `POST /api/v1/kag/answer` | as-of 时点问答，返回结论+引用+释放/弃权（§5） | 依场景 |
| KAG | `GET /api/v1/kag/diff?t1=&t2=` | 时点差分（§5.3） | 依场景 |
| 撮合·找学生 | `GET /api/v1/matching/students?geo=&subject=&time=` | 找学生（§6.1） | **仅 independent_tutor** |
